# 11/25 — 포인터와 부분 배열을 활용한 함수 재사용

[실행 예제](array.c)의 `sum_array`에 시작 위치와 원소 개수를 전달하면 같은 함수로 전체 배열과 원하는 연속 구간의 합을 구할 수 있다.

## 배열과 포인터 표현식

| 표현식 | 이 예제에서의 의미 |
| --- | --- |
| `arr` | 함수 인수로 전달될 때 첫 번째 원소의 주소로 변환된다. |
| `arr + 2`, `&arr[2]` | 세 번째 원소의 주소다. |
| `*(arr + 2)`, `arr[2]` | 세 번째 원소의 값 `9`를 읽는다. |

`arr + 1`은 `int` 한 개만큼 이동한다. 예제는 주소를 `%p`로 출력할 때 `void *`로 변환하고, `sizeof(int)`의 결과를 `%zu`로 출력한다. 주소와 `int`의 바이트 크기는 실행 환경에 따라 달라질 수 있다.

## 함수에 넘기는 값

`const int *arr`는 함수가 이 포인터를 통해 원소를 읽을 수 있게 하고, 이 포인터를 통한 원소 쓰기는 막는다. `main`에서 선언한 배열은 해당 범위에서 여전히 수정할 수 있다.

포인터 매개변수에는 시작 주소가 복사된다. 함수의 `arr[0]`은 전달받은 시작 위치의 원소다. 따라서 호출자가 원본 배열의 두 번째 인덱스를 넘기면 함수 안의 첫 원소는 원본의 `arr[2]`가 된다. 읽을 원소 개수는 `len`으로 따로 전달한다.

## 배열 범위 확인

전체 길이가 `n`이고 시작 인덱스가 `offset`이면, 먼저 `0 ≤ offset ≤ n`을 확인한 뒤 `0 ≤ len ≤ n - offset`을 확인한다. 길이 5인 배열의 인덱스 2부터는 원소가 3개 남는다. `arr + n`은 마지막 원소 바로 다음을 가리킬 수 있으며, 그 위치에서 읽을 수 있는 원소 수는 0이다.

함수가 호출자가 전달한 길이만큼 읽으려 하므로 호출 전에 범위를 확인해야 한다. 배열 범위 밖 읽기(Out-of-Bounds Read)는 C에서 정의되지 않은 동작이다. 충돌이나 메모리 정보 노출로 이어질 수 있고, 겉으로 정상 동작하는 것처럼 보일 수도 있다.

`len`이 0이면 예제의 반복문은 원소를 읽지 않고 0을 반환한다. 합의 자료형은 `int`이므로 중간 합도 `int` 범위 안에 있어야 한다.

## 실습 확인

| 호출 | 읽는 원소 | 예상 합 |
| --- | --- | ---: |
| `sum_array(arr, 5)` | 3, 6, 9, 12, 15 | 45 |
| `sum_array(arr + 2, 3)` | 9, 12, 15 | 36 |
| `sum_array(arr, 2)` | 3, 6 | 9 |
| `sum_array(arr + 1, 3)` | 6, 9, 12 | 27 |
| `sum_array(arr + 4, 1)` | 15 | 15 |
| `sum_array(arr, 0)` | 없음 | 0 |
